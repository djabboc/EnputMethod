## 已知限制与明确延后项

| 编号 | 项目 | 原因与后续边界 |
| --- | --- | --- |
| D-01 | 横向布局的导航轴 | 已确认合理目标：纵向为上下选择、左右翻页；横向为左右选择、上下翻页，快捷键跟随布局。用户明确要求暂不修改；任务见 `pending-layout-navigation-zh-CN.md`。 |
| D-02 | 日文完整词典 | 当前仅有示例日文映射。完整英日数据应使用 JMdict，并遵循 CC BY-SA 4.0 的署名和相同许可要求；不能把 ECDICT 伪称为完整日文词典。 |
| D-03 | 翻译数据完整性 | `translations.json` 是用户可覆盖的小型 JSON 词典；ECDICT 提供大规模英中覆盖，但不保证每个词都有完整例句或所有语言映射。未下载、下载失败或转换失败时仍会回退到小词典。 |
| D-04 | 应用更新生效条件 | TSF DLL 在目标应用进程内加载。更新后仅切换输入法不能保证换用新 DLL，必须关闭并重开目标应用；安装提示先切换其他输入法是刷新 Profile 可见性，不是解除 DLL 占用的唯一手段。 |
| D-05 | 最终体验判定 | 候选窗口属于跨应用 TSF UI，视觉闪烁、焦点和鼠标命中必须在真实应用中验收；静态构建不能替代人工验证。 |
| D-07 | 字母数字标识符中的数字键歧义 | 候选可见时，`1` 至 `9` 当前优先作为直选候选键。因此输入 `dota` 后按 `2` 会提交第 2 个候选（例如 `dotages`），而不是把 `2` 写入活动 composition 形成 `DOTA2`。一个按键不能无歧义地同时表示文字与选词。对于英文输入法，较合适的后续方向是让字母数字串优先输入数字，并保留 Tab/方向键/鼠标或带修饰键的数字选词；也可作为配置项。用户明确要求暂不修改。 |

## 集中验收顺序

安装最新版本后，先切换到其他输入法再切回 Enput Method，并重开每个待测应用。每项记录“通过”或实际文本/窗口行为。

1. `hel` 左移、输入 `s`，预期 `hesl`，候选窗不消失。
2. `he`、`?`、空格，预期 `he? `。
3. 输入 `t`，用 `+`、`-` 与鼠标 `<`、`>` 往返分页；前缀不提交，窗口位置稳定，鼠标按钮有手型和高亮。
4. 在首项长按上键、在第一页长按 `-`，再进行正常翻页；不应有明显闪烁或整体位移。
5. 鼠标选择非首项，预期完整候选写入；若有后续关联，候选窗继续显示下一个词/短语。
6. 输入 `how` 后选择 `how`，再选择 `are you`，预期 `how are you`，不重复 `how`。
7. F2 输入 `smile`、`cry`，预期彩色 Emoji、英文提示、统一字号、稳定切换；选择后写入 Emoji。
8. F3 依次高亮 `hello`、`hell`、`abandon`，预期翻译窗在候选窗旁、随高亮更新；`abandon` 验证 ECDICT 数据。
9. 分别输入 `enter`、`Ent`，以及开启 Caps Lock 和 Caps Lock + Shift；候选大小写符合实际输入，CAPS 标记不重叠页码。
10. 恢复默认配置后验证纵向 9 项；再按自定义配置验证横向 3 项、Consolas 18、透明度、Tab 不追加空格。横向导航轴现状只记录，不作为本轮通过条件。
11. 在 Notepad、EmEditor、ChatGPT 各重复第 1、2、3、5 项。

### 自动化真实 TSF 验收方法（2026-09-06）

TSF 运行时改动的自动化验收固定分层：先执行 Release 构建和相关回归，再重建并授权安装本地包，最后运行 `scripts\run-tsf-integration-tests.ps1 -Configuration Release`。该脚本建立隔离 x64 WPF 测试宿主，经 `ITfInputProcessorProfileMgr` 只对该进程启用已安装的 Enput Profile；它以 `SendInput` 送入实际按键，随后读取真实编辑控件的文本和光标状态断言。因此它能证明已安装 TSF 的按键路由、composition 和候选提交是否生效，而不影响用户其它进程的输入法状态。

自动化提交普通候选使用内置数字直选。WPF `TextBox` 对 Tab 的路由不代表目标编辑器，故 Tab 另列为 Notepad、VS Code 或用户目标编辑器抽测项。测试不假定候选排序：需要特定候选时通过真实 composition 预览逐项定位。仅当测试窗口附着交互桌面，且 `SendInput`、原生窗口发现和 Profile 激活均成功时，脚本通过才是有效的真实宿主证据；任何一项不可用都必须标为阻塞，不能用构建、安装或 SQLite 审计替代。

## 2026-08-30：重点复盘 - 近一小时 TSF 安装事故

本轮从用户报告“卸载成功但旧宿主仍可输入、重装在 TSF 分类阶段失败、微软中文输入法异常”到用户确认最终成功，实际排查、修复、构建和真实 UAC 复验接近一小时。这一耗时不应被视为普通安装波动：失败安装曾留下半注册 TIP，并对当前 Windows TSF 会话产生可见影响。以下内容作为发布与调试的强制经验记录。

### 事故链

1. 用户先卸载 Enput。已打开应用继续使用内存中映射的旧 TSF DLL，这是“只注销注册、不删除运行文件”策略的预期行为，不代表卸载失败。
2. 用户从 WPF 安装器点击安装。GUI 原本用 `Task.Run` 调用原生 TSF 注册，线程池为 MTA；TSF Profile 和 Category 注册却要求 STA。
3. 原生层收到 `RPC_E_CHANGED_MODE` 后没有立即停止，继续注册 COM、Profile 和语言项，随后在核心键盘分类阶段失败。Profile 曾被提前启用，故 Enput 会短暂出现在输入法列表。
4. 半注册 TIP 使当前 TSF/ctfmon 会话异常，用户看到微软中文输入法似乎“死掉”；重启 Windows 后会话缓存重建，半注册项被隐藏，微软拼音恢复。这不是代码删除了微软拼音注册表。
5. 早期无界面 `--install-and-verify` 从 WPF 启动 STA 执行，曾能成功，从而错误地给出“安装正常”的信号；它没有覆盖 GUI 的 MTA 路径。旧自动化也没有把卸载和紧随其后的重装纳入同一条回归链。

### 已固化的修复

- 安装器按钮、卸载器按钮及两个无界面入口统一经专用 STA 工作线程调用原生 TSF；STA 初始化失败在任何注册前直接返回。
- TSF 安装按事务处理：先注册服务和 Profile，先保证核心键盘分类，再启用 Profile；`TF_E_ALREADY_EXISTS` 是可重试的幂等结果，immersive 分类仅为可选能力。
- 任一安装步骤失败都会清理 **仅属于 Enput** 的 Profile、分类、HKCU/HKLM `CTF\\TIP\\{9C8945D5-...}` 根和 CLSID，并保留最初的失败阶段/HRESULT。代码绝不遍历、删除或改写 Microsoft Pinyin 的 `{81D4E9C9-...}`。
- 卸载成功不再只相信原生返回码；卸载器会检查 Enput 的 COM 与 TIP 根确实不存在。DLL、Overlay、静态资源和用户配置刻意保留，让已打开宿主不会因缺依赖崩溃，也支持不重启立即重装。
- 安装成功也不再只检查 COM DLL：还必须看到 Enput 中文 LanguageProfile 与核心键盘分类，否则向用户报告失败。

### 经验与教训

1. **自动化必须走与用户相同的执行路径。** “无界面成功”不能证明“点击 GUI 成功”；线程单元模型、同步上下文和 COM 初始化均可能不同。共享一个可测的 STA 执行器后，两个入口才有可比性。
2. **Windows 输入法注册不是一组可随意重试的独立写入。** COM、Profile、Category 和启用状态必须作为事务；任何中途失败都必须回滚 Enput 自己的全部入口，且启用动作应放到最后。
3. **“旧应用仍能工作”与“新安装可以使用”是两个状态。** 卸载时保留被映射 DLL 是正确的兼容策略；判断卸载完成应检查未来激活入口是否移除，不能要求用户关闭所有应用，更不能为了删除文件破坏当前宿主。
4. **错误信息和日志必须属于本次操作。** GUI 失败必须覆盖写安装日志；包校验、词库校验和 TSF 安装日志不可复用，否则旧成功日志会掩盖真实失败。
5. **发布验收必须验证完整生命周期。** 当前 `scripts/run-regression.ps1` 的强制顺序是“构建 -> Overlay/原生测试 -> 安装 -> 无界面卸载验证 -> 不重启立即重装”。卸载验证同时检查 Enput 注册清理、共享文件与用户配置保留、以及非 Enput 输入法项未变化。
6. **必须诚实记录测试边界。** 现有回归已覆盖真实 STA 正常链路和立即重装，但尚未有完全确定性的“强制核心 Category 注册失败”注入测试。后续应增加只在测试环境显式启用的失败钩子或隔离集成环境，验证失败回滚和微软拼音基线保持不变；不得通过修改系统注册表 ACL 人为制造故障。

### 本次可复用结论

对于当前已发布的修复，用户不需要在每次安装/卸载后重启；真实 UAC 链路已经验证可以立即重装。只有旧版半注册状态已经让某个已打开应用持有异常 TSF 会话时，关闭该应用或重启一次才是清除历史缓存的恢复手段，而不是新版安装流程的常规要求。

- 原因：`WS_EX_NOACTIVATE` 用于保持编辑器的 TSF 焦点，而默认 `RichTextBox` 选区路径会尝试获取键盘焦点；两种行为互相冲突。
- 早期尝试：曾实现预览鼠标选区，将拖动坐标映射至 `TextPointer` 范围，并保留滚动条的原生输入。该实现使产品语义复杂且没有满足实际需求。
- 最终决定：已删除这套鼠标拖选和右键复制实现。翻译窗口保持不抢焦点；用户通过标题栏 `Copy` 按钮复制完整翻译，成功后短暂显示 `✓ Copied`。
- 验证：Overlay 自动化验证 Copy 动作、剪贴板写入和成功反馈的超时恢复；不再声称支持鼠标框选文本。
